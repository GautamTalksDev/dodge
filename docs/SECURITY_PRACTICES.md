# Security practices

What DODGE does to stay trustworthy, and the standard each control comes from. Threats and their mapping to the OWASP Top 10:2025 are in [THREAT_MODEL.md](THREAT_MODEL.md).

## 1. CI/CD (OWASP Top 10 CI/CD Security Risks)

| Risk | Control in this repository |
|---|---|
| CICD-SEC-1 Insufficient flow control | `main` protected by a ruleset: pull requests, required checks, no force pushes or deletion |
| CICD-SEC-2 Inadequate identity and access | One maintainer, passkey 2FA on GitHub and Cloudflare. No personal access tokens in workflows |
| CICD-SEC-3 Dependency chain abuse | Actions pinned to full commit SHAs. Python dependencies pinned with hashes and installed with `--require-hashes --no-deps`. Dependabot with a 7 day cooldown |
| CICD-SEC-4 Poisoned pipeline execution | No `pull_request_target` or `workflow_run`. Untrusted values reach shell only through `env:`, never `${{ }}` inside `run:`. Fork pull requests run `ci.yml` only, read-only |
| CICD-SEC-5 Insufficient pipeline access control | Top-level `permissions: {}`. Jobs that run third-party code (numpy, sgp4) hold `contents: read` only. Writing happens in separate `publish` jobs that run no third-party code |
| CICD-SEC-6 Insufficient credential hygiene | No long-lived secrets in workflows. `persist-credentials: false` on every checkout. Secret scanning with push protection |
| CICD-SEC-7 Insecure system configuration | GitHub-hosted runners only. `step-security/harden-runner` audits every outbound connection |
| CICD-SEC-8 Ungoverned use of third-party services | Only GitHub, CelesTrak, PyPI, Sigstore and Cloudflare. Each is listed in [ARCHITECTURE.md](ARCHITECTURE.md) |
| CICD-SEC-9 Improper artifact integrity validation | Chained SHA-256 manifests and Sigstore attestations on every daily output |
| CICD-SEC-10 Insufficient logging and visibility | `data/runs.ndjson` logs every recorder run. Workflow failures notify the maintainer. CodeQL, zizmor and Scorecard results appear in the Security tab |

Automated checks on every change: `ci.yml` (tests, compile, script parse, dash check), `codeql.yml` (Python, JavaScript, Actions), `zizmor.yml` (workflow linting), `dependency-review.yml` (pull requests), `scorecard.yml` (OpenSSF Scorecard, published).

## 2. Supply chain (OpenSSF Scorecard and SLSA)

* **Pinned dependencies:** every `uses:` is a 40 character commit SHA with the version in a comment. `requirements.txt` lists exact versions and the SHA-256 of every wheel for Linux, macOS and Windows.
* **Build provenance:** each day's outputs are attested with `actions/attest` (Sigstore). That is SLSA Build Level 2: provenance generated by a hosted build platform, signed, and verifiable by anyone.
* **No binaries in the repository.** Data lives in releases and on the `data` branch.
* **Self-hosted fonts and no third-party scripts** on the website, apart from Cloudflare's own analytics beacon, which the CSP allows by origin.

### Dependencies

To update a dependency, change the version and regenerate the hashes:

```bash
pip download --only-binary=:all: --python-version 3.12 --platform manylinux_2_28_x86_64 numpy==X sgp4==Y -d w
pip download --only-binary=:all: --python-version 3.12 --platform macosx_14_0_arm64 numpy==X sgp4==Y -d w
pip download --only-binary=:all: --python-version 3.12 --platform win_amd64 numpy==X sgp4==Y -d w
sha256sum w/*.whl
```

Then rerun the tests and the recall check ([VALIDATION.md](VALIDATION.md)) before merging.

## 3. Data integrity

Every UTC day has a release, `day-YYYY-MM-DD`. It fills up during the day: recordings every 4 hours, then that day's screen. The next morning's screen run **seals** it:

1. `tools/manifest.py` writes `manifest-YYYY-MM-DD.json` with the SHA-256 and size of every file in the release, and the SHA-256 of the previous day's manifest.
2. The `attest` job writes `SHA256SUMS-<today>` over that manifest and every file published today, and signs it with `actions/attest`. The bundle is uploaded as `attestation-<today>.sigstore.json`, and the signature is recorded in the public Rekor transparency log.

Changing any past file changes its manifest hash, which breaks every later link in the chain, and no attestation will cover the changed file. How to check: [VERIFYING.md](VERIFYING.md).

## 4. Website (OWASP ASVS 5.0, Level 1, with Level 2 for V3)

* **Content Security Policy:** `default-src 'none'`, then only what the page needs. Scripts, styles and fonts from the site itself; data from `raw.githubusercontent.com`; Cloudflare's analytics beacon. No inline scripts or styles: dynamic values are set through the CSSOM.
* **Trusted Types:** `require-trusted-types-for 'script'` with one named policy, `dodge`. HTML reaches the page only through it, and every data value is escaped before it is placed in a template. Satellite names come from a third party and are treated as untrusted text.
* **Other headers:** HSTS (two years, subdomains), `X-Content-Type-Options`, `X-Frame-Options: DENY` and `frame-ancestors 'none'`, `Referrer-Policy`, `Cross-Origin-Opener-Policy`, `Cross-Origin-Resource-Policy`, and a `Permissions-Policy` that turns off every powerful feature. These follow the OWASP Secure Headers Project.
* **No state:** no cookies, no storage, no forms, no accounts. See the [privacy page](https://dodge.gautamkhosla.com/privacy/).
* **security.txt** (RFC 9116) at `/.well-known/security.txt`.

## 5. Upstream etiquette (availability)

CelesTrak is a free service run for the community. The recorder makes one request per source per run, every 4 hours, at an off-minute, and stops on any unexpected response instead of retrying. That keeps DODGE well inside CelesTrak's [usage policy](https://celestrak.org/NORAD/documentation/gp-data-formats.php), and avoids getting shared runner addresses blocked.

## 6. Repository settings the maintainer keeps on

* Actions: default token read-only; Actions cannot create or approve pull requests; actions must be pinned to a full SHA.
* Secret scanning and push protection; Dependabot alerts and security updates; private vulnerability reporting.
* Ruleset on `main`: require pull requests, required status checks (`ci`, `codeql`), block force pushes and deletion, linear history.
* Passkey 2FA on GitHub and Cloudflare.
